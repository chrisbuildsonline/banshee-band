# Design: Listening live (F9b)

Requirement numbers refer to `requirements.md`.

## Overview

Two additions to the listening station, one shared by both.

```
Start listening (click)                                         listen.ts   DOM: card, status, Start/Stop
   |  createClassifier() on first use (shared with Try a sound)
   |  capture.start({ kind: 'mic' })                            src/audio createCapture
   v
capture.onStereoFrame ---------> bearingWindow.push(frame)      src/bearing createBearingWindow
capture.onMonoFrame ----------> live.ts window queue (newest wins, one classify at a time)
                                   classify(window.samples)     src/classify  (t0, t1 from injected now())
                                   gate (class != other, 3 s cooldown per class)      live-gate.ts
                                   processEvent({ classification, bearing = window.result(),
                                                  loudnessDb = rmsDb(window), id: live-n })  pipeline.ts
                                   outputs.play(command)        simulator, phone when available()
   v
LiveUpdate (plain data) -> station.ts applies it: ghostField.show, list.add, pipeline.show

Build:  vite build -> plugin emits sw.js (precache list injected) + manifest check
Page:   register.ts (prod only) -> /sw.js -> install precaches ~17 MB -> message 'precache-complete'
Offline: navigation -> cached index.html; model.json and shards -> cache (ignoreVary)
```

The clip path (`runSound`) is untouched. Live and clip runs share the classifier, the ghost field, the list, the pipeline view and the output list. They use separate haptic engines (Requirement 3.7).

## Listen: types

```ts
export type ListenState = 'idle' | 'starting' | 'listening' | 'stopped' | 'blocked' | 'problem';

export interface LiveDeps {
  capture: Pick<Capture, 'start' | 'stop' | 'onMonoFrame' | 'onStereoFrame' | 'onStateChange'>;
  classifier: Pick<Classifier, 'classify' | 'backend'>;
  bearing: BearingWindow;                 // createBearingWindow()
  engine: HapticEngine;                   // createHapticEngine() default rate limit
  outputs: readonly HapticOutput[];
  now(): number;                          // performance.now()
  epoch(): number;                        // Date.now()
}

export type LiveUpdate =
  | { kind: 'event'; result: RunResultOk }       // same shape as a clip run, frames: 1, chosen: null
  | { kind: 'failure'; code: 'classify-failed' | 'event-invalid' }   // after 5 in a row: stop
  | { kind: 'state'; state: ListenState; message: string | null };
```

`RunResult` gains `chosen: TrySide | 'live'` and a `backend: string` field, so the pipeline view takes one shape for both paths. The clip path sets `backend` from `classifier.backend`. This is an additive change to `types.ts` and to the `runner.ts` return value; `runner.test.ts` literals gain `backend`.

## Live loop (Requirements 3.1 to 3.9)

```ts
export function createLive(deps: LiveDeps, onUpdate: (u: LiveUpdate) => void): {
  start(): Promise<void>; stop(): Promise<void>; readonly dropped: number;
}
```

- `start()` subscribes to the three capture streams, then `await capture.start({ kind: 'mic' })`. State changes from `onStateChange` map through `listenStateFor` (`listen-status.ts`): `starting` to Starting, `listening` to Listening, `idle` to Stopped (after a Stop), `error` with `permission-denied` to Mic blocked, any other error to Problem. The message is the capture error's `message` (already plain language, never a raw value).
- Stereo frames: `deps.bearing.push(frame)` directly. Mono frames: `pending = frame` (a frame already pending counts as dropped). If no classification is running, take `pending`, run it.
- One window: `t0 = now()`, `await classifier.classify(frame.samples)`, `ms = now() - t0`. Then `gate.accept(cls, epoch)`. Rejected windows still update the pipeline view's Label tile (`kind: 'event'` is sent only for accepted windows; rejected ones send nothing, so a quiet room shows nothing and does no work beyond classify).
- Accepted: `processEvent({ classification, bearing: deps.bearing.result(), loudnessDb: rmsDb(frame.samples), nowMs: t0, id: 'live-' + n }, deps.engine)`; on `play`, every available output `play(command)`; the update carries peaks (`waveformPeaks(frame.samples, PEAK_BUCKETS)`), `seconds: 1`... the window is 0.975 s, shown as "1.0 s" by `toFixed(1)`; `times` has `label = ms`, the other stages measured with the same injected `now()` pairs.
- Failures: a counter of failed classifications in a row. The fifth sends `{ kind: 'failure' }` then `stop()`.
- `stop()`: unsubscribes, `await capture.stop()`, drops `pending`, resets the bearing window. A classification that finishes after stop is ignored (generation counter, as in `src/audio/capture.ts`).
- Tests use a fake `capture` that lets the test push stereo and mono frames and states, and a scripted clock. Frames are `Float32Array(15600)` built from the real clip WAV in one integration test so `classify` is a stub but `processEvent` and the real engine run.

### Gate

```ts
export const LIVE_COOLDOWN_MS = 3000;
export function createLiveGate(options?: { cooldownMs?: number }): { accept(cls: SoundClass, nowMs: number): boolean };
```

`other` returns false and does not start a cooldown. A class returns true when it has no earlier accepted time, or `nowMs - last >= cooldownMs`; then `last` is set. A negative or `NaN` `nowMs` returns false. Test literals: knock at 0 true, knock at 2999 false, knock at 3000 true, doorbell at 100 true after knock at 0.

## Listen card (Requirement 2)

DOM, inside `[data-card="listen"]`, class `bb-card bb-station-listen`:

```
<section class="bb-card bb-station-listen" data-card="listen" aria-labelledby="listen-title">
  <h2 class="bb-heading" id="listen-title">Listen</h2>
  <p class="bb-station-listen__note">Banshee Band listens through your microphone ... never recorded or sent anywhere.</p>
  <div class="bb-station-listen__row">
    <button type="button" class="bb-pill bb-pill--primary" data-listen="start">Start listening</button>
    <!-- while listening: <button type="button" class="bb-pill bb-pill--secondary" data-listen="stop">Stop</button> -->
    <span role="status" class="bb-status bb-status--accent" data-listen-state="listening">...glyph Listening</span>
  </div>
  <p class="bb-station-listen__message" role="status" aria-live="polite"></p>
</section>
```

Class names follow `src/ui/styleguide.css`; the builder checks the primary pill class name there and reuses it (DESIGN.md Components, Pills). The status pill reuses the `bb-status` markup of `status.ts`. Rather than copy it, move the glyph drawing into a small shared helper in `status.ts` (`statusPill(container, table)`) and have the output pill and the listen pill use it. Table:

| State | Word | Glyph | Tint |
|---|---|---|---|
| idle | (pill hidden, no text) | | |
| starting | Starting | open circle | neutral |
| listening | Listening | filled circle | accent |
| stopped | Stopped | square | neutral |
| blocked | Mic blocked | cross | strong |
| problem | Problem | cross | strong |

Two live regions in one card would announce twice, so the pill is the `role="status"` and the message paragraph has no role of its own; the message is placed inside a second `aria-live="polite"` region only when text exists. The builder checks with the screen-reader text order (status first, then message) and keeps one announcement per change.

Focus: the click handler swaps the buttons, then `stopButton.focus()` (and `startButton.focus()` on stop or error). `aria-disabled` on Start while starting.

The status table in `design/DESIGN.md` gets two rows: "Stopped, Stopped, square, neutral" and "Mic blocked, Mic blocked, cross, strong". The Paused row stays for other screens.

Phone bar: a wrapper `<div class="bb-station-controls">` holds the Listen card and Try a sound card. On phone it is `position: fixed; bottom: 0` and the `ResizeObserver` observes the wrapper instead of the Try card. The Listen card is compact on the bar (the note is hidden under the status row on phone: collapsed to a one-line "Processed on this device" caption; the full sentence stays in the DOM for desktop and is shown in the `<details>`-free way by CSS only if there is room). To keep the bar short: the note moves under the title block on phone through CSS `order`. The builder measures the bar at 390 x 844 and keeps chips and side control in the lower 45%.

## Label tile (Requirement 4)

```
Label                              38 ms
Dog bark, 91%
Class: Knock
Backend: webgl            <- data-backend="webgl"
Classify: 3 ms per window <- data-classify-ms="3.1"
```

`classifyText(ms)` in `format.ts`: "Classify: 3 ms per window" using `formatMs` rules. For a clip run `ms = times.label / frames`. For a live window `ms` is the single classify time. `classifier.backend` is read once at creation. The tile text before any run is unchanged.

`createClassifier` change (`src/classify/classifier.ts`): after `await tf.ready()`, `const backend = tf.getBackend() || 'unknown'`, returned as `backend` on the object. `tests/classify` gets one case with a mocked `tf` where it exists, or an assertion that the real CPU run in Node reports `'cpu'`.

## PWA

### Precache list and cache name (pure)

```ts
export function buildPrecacheList(input: {
  bundleFiles: readonly string[];     // from the Vite bundle: html, js, css, assets
  publicFiles: readonly string[];     // relative paths under public/
  clipNames: readonly string[];       // from public/clips/manifest.json
}): string[]                          // sorted, unique, URL paths with a leading slash
export function cacheNameFor(list: readonly string[]): string      // 'banshee-' + 8 hex of FNV-1a over the joined list
```

Rules: include `index.html`, `band.html`, `styleguide.html`, and every bundle file except `*.map`; include `favicon.svg`, `manifest.webmanifest`, `icons/*.png`, `models/yamnet/model.json`, `models/yamnet/*.bin`, `models/yamnet/yamnet_class_map.csv`, `clips/manifest.json` and `clips/<name>` for each name; exclude `sw.js`, `LICENSE.txt`, `SHA256SUMS`, `*.md`. A test lists the exact expected output for a small literal input. Hashed bundle names change when content changes, so the cache name changes with them. Public files have stable names, so the name hashes the list only; to avoid a stale model after a content-only change, the plugin also mixes `sha256` of the public files' sizes into the hash input (sizes are cheap; `cacheNameFor` takes `list` entries as `path` or `path?size`; the URL fetched is the path without the size).

### Routes (pure)

```ts
export type Route = { kind: 'navigate'; key: string } | { kind: 'asset'; key: string } | { kind: 'ignore' };
export function routeFor(r: { url: string; method: string; mode: string; origin: string }): Route
```

- Another origin, a non-`GET` method, an unparseable URL, `/sw.js`: `ignore`.
- `mode === 'navigate'`: `/` and `/index.html` give key `/index.html`; `/band.html` and `/styleguide.html` give themselves; a path ending in `.html` that is not precached or any other path gives `/index.html` (a path with a file extension other than `.html` gives `ignore`).
- Otherwise: `asset` with the key `pathname` (query and hash dropped).

`routeFor` never throws, including for `'not a url'`, empty strings and `null`-like input cast to string.

### Worker (`src/pwa/sw.ts`)

```ts
const PRECACHE = '__PRECACHE_LIST__';   // replaced by the plugin with a JSON string of the list
const CACHE = '__CACHE_NAME__';
install:  event.waitUntil(precacheAll().then(() => self.skipWaiting()))
activate: event.waitUntil(deleteOldCaches().then(() => self.clients.claim()).then(notifyClients))
fetch:    const route = routeFor(...); if (route.kind === 'ignore') return;
          event.respondWith(caches.open(CACHE).then(c => c.match(route.key, { ignoreVary: true }))
              .then(hit => hit ?? fetch(event.request)))
```

`precacheAll` fetches each URL with `{ cache: 'reload', credentials: 'omit' }` one after another (the model shards are 4 MB each, so a failed one is easy to see), `response.ok` is required, then `cache.put`. Sequential fetches keep memory flat. The `notifyClients` message is also sent after install completes, because a page opened before activation needs it (`clients.matchAll({ includeUncontrolled: true })`). A page that loads when the worker is already active asks with `postMessage({ type: 'status' })` and gets the answer.

`Response` bodies can be used once, so `put` receives `response.clone()`. The worker is written in TypeScript with `/// <reference lib="webworker" />` in `src/pwa/sw.ts` and its own `tsconfig` include check is covered by `bun run typecheck`; if the root tsconfig cannot hold both DOM and WebWorker libs, the builder uses a `src/pwa/tsconfig.sw.json` and adds it to the `typecheck` script.

### Build plugin (`vite.config.ts`)

A plugin object `{ name: 'banshee-pwa', apply: 'build', generateBundle, writeBundle }`:

1. `generateBundle`: collect `Object.keys(bundle)`, read `public/` with `node:fs` (recursive), read `clips/manifest.json`, call `buildPrecacheList` and `cacheNameFor`.
2. Compile `src/pwa/sw.ts` as an extra rolldown input with `fileName: 'sw.js'` (no hash), then replace the two placeholders in the emitted chunk with the JSON list and the cache name. If rolldown cannot emit an unhashed entry, use `this.emitFile({ type: 'prebuilt-chunk' ... })` after compiling with `vite`'s `transformWithEsbuild` equivalent. The builder picks what works with the installed Vite 8 and records the choice here.
3. Fail the build when a URL of the list is missing from `dist/` or the list is larger than 40 MB.

`vite.config.ts` gains `preview: { port: 5288, strictPort: true }`.

### Register (`src/pwa/register.ts`)

```ts
export function registerServiceWorker(): void
```

Returns at once unless `import.meta.env.PROD && 'serviceWorker' in navigator`. On `window` load it registers `/sw.js`, listens for `{ type: 'precache-complete' }`, sets `window.__bbOffline = { ready: true }` and `document.documentElement.dataset.offlineReady = 'true'`, and shows the muted line (Requirement 7.3) through a `[data-offline-note]` element in `index.html` that CSS hides until the attribute is set. A rejected registration is swallowed without `console` output (the app works without it).

### Manifest and icons

`buildManifest({ name, shortName, background, theme, icons })` returns the object; `scripts/make-icons.ts` also writes `public/manifest.webmanifest` from it, with the colours read from `src/ui/tokens.css` by a regex on `--bb-color-canvas` and `--bb-color-accent` (Day values; a test fails if either is not found).

`renderIcon(size, kind: 'any' | 'maskable'): Uint8ClampedArray` renders by signed distance, no SVG rasteriser: a disc in the accent colour (full square for `maskable`), a canvas-colour ghost (a circle head of radius 0.26 size at (0.5, 0.42), a body rectangle below it down to 0.74, a three-scallop hem of circles of radius 0.0867 size), two accent eyes at (0.42, 0.45) and (0.58, 0.45) of radius 0.045 size, with 4x4 supersampling. The maskable ghost is scaled to 0.8 around the centre. `scripts/make-icons.ts` writes PNGs with a hand-written chunk writer (signature, `IHDR`, one `IDAT` through `zlib.deflateSync` with fixed level 9, `IEND`, CRC-32 table). Same input gives the same bytes, and a test compares two renders and checks that the PNG signature, size fields and an eye pixel are right.

## Playwright

`e2e/live.spec.ts` (dev server, project `chromium`):

```ts
test.use({ launchOptions: { args: [
  '--use-fake-device-for-media-stream', '--use-fake-ui-for-media-stream',
  `--use-file-for-fake-audio-capture=${KNOCK_WAV}`,
] } });
```

Cases: Start gives "Listening" and focus on Stop; a Knock row appears within 60 s (model load first); the Label tile has `data-backend` of `webgl` or `cpu` and a `data-classify-ms` that is a positive number; Stop gives "Stopped", every track `readyState === 'ended'` (a `getUserMedia` wrapper from `e2e/audio-capture.spec.ts` records the streams); no `getUserMedia` call before the click; denied permission (init script that makes `getUserMedia` reject with a `DOMException('', 'NotAllowedError')`) gives "Mic blocked" and the message from `CAPTURE_MESSAGES['permission-denied']`; the keyboard flow; reduced motion; console without errors.

`e2e/offline.spec.ts` (project `offline`: `webServer` runs `bun run build && bun run vite preview --port 5288`, `baseURL` 5288, `testMatch: /offline\.spec\.ts/`; project `chromium` gets `testIgnore` for it):

1. Visit `/`, wait for `data-offline-ready="true"` (timeout 120 s: 17 MB), check `navigator.serviceWorker.controller` is set after one reload, manifest link and icons answer 200.
2. `context.setOffline(true)`, reload, expect the `h1` "Listening station", press Knock, expect a Knock row (timeout 120 s), console clean.
3. Offline reload of `/band.html`.
4. Requests: `context.on('request')` collects every URL for the whole test, including the worker's; expect all to have the page origin, and every path to be in the precache list read from `dist/sw.js` (parsed in the test) or be `/sw.js`, `/` or an HTML page.

Both specs fail on `pageerror` and on any `console` message of type `error`. Existing specs keep running on the dev server.

## Decisions for the owner

- A second Listen status pill rather than one pill for both outputs and listening (Introduction). Reason: the output pill describes the band, the Listen pill describes the microphone, and they change at different times.
- A fixed 3 s cooldown per class and `other` is never shown live. Without it a loud steady sound would fill the ghost field and the log every 0.4875 s.
- Live and clip runs use separate engines so Try a sound keeps `rateLimitMs: 0`.
- Precache is all-or-nothing and about 17 MB. A user on a mobile connection downloads it once, at first visit, without asking. If that is too heavy, the builder can move the model to "cache on first Start listening or first chip", at the cost of Requirement 7.1 after only a visit.
- The service worker runs only in production builds, so development never serves stale files.
